================================================================
0. 一分钟速览
================================================================
这是一个安卓 App，插上免驱 UVC（USB Video Class）摄像头后可以：
全屏预览、拍照、录像、切换分辨率/格式、旋转镜像、悬浮窗显示、
用外接键盘的热键一键拉起/一键退回后台、进入全屏时暂停其它媒体并播报
“请小心驾驶”的内置提示音。

关键点（最容易跑偏的地方）：
- 不用系统 Camera2，也不依赖“外接相机”支持，走 libuvc 直接读 USB 视频流。
- 不用任何 Material / AppCompat 的 UI 组件，界面全部用 Kotlin 代码搭。
- 全局热键依赖“无障碍服务”，这是 Android 上唯一免 root 的后台收键方案。
- 悬浮窗依赖“显示在其他应用上层”权限 + 前台服务常驻。
- 默认横屏（sensorLandscape）。


================================================================
1. 产品目标与使用场景
================================================================
1.1 目标用户
    车载（车机/平板）场景为主，其次为工业现场、门店监控。
1.2 典型使用流程
    a) 车机开机，插着 USB 摄像头和 USB 键盘。
    b) 平时在跑导航/桌面。
    c) 按快捷键 F8 → App 被拉起，横屏全屏出画面，同时音乐暂停、
       播报“请小心驾驶”。
    d) 看几秒后按退出键 F9 → App 退回后台，导航界面回来，音乐自动续播。
    e) 也可以开启悬浮窗，让摄像头小窗浮在导航上层长时间显示。
1.3 非目标（明确不做）
    - 不做云端推流、不做人脸识别、不做视频文件管理界面。
    - 不做系统相机（Camera2）混合预览。


================================================================
2. 技术选型与硬性约束
================================================================
2.1 技术栈（版本已固定，不要随意升级）
    - 语言：Kotlin 2.0.21
    - 构建：Gradle 8.9 + Android Gradle Plugin 8.7.3，JDK 17
    - compileSdk 35 / targetSdk 34 / minSdk 24
    - 依赖只有一条：
        implementation 'com.herohan:UVCAndroid:1.0.13'
      来源 Maven Central（不需要 JitPack），内部是 libuvc + libusb
      + libjpeg-turbo，Apache-2.0。
    - 仓库里没有 gradle-wrapper.jar（二进制文件），CI 里手动装 Gradle 8.9。

2.2 硬性约束（违反会导致编译失败或行为偏差）
    - 不要引入 Material Components / ViewBinding / Compose / Fragment。
      所有界面用 android.* 原生控件在 Kotlin 里 new 出来。
    - Activity 继承 android.app.Activity（不是 AppCompatActivity）。
    - 主题用 @android:style/Theme.Material.NoActionBar。
    - 包名 / namespace / applicationId 都是 com.usbcam，不要改。
    - 不要引用 Android 的 @hide 常量（例如 KeyEvent.META_MODIFIER_MASK），
      公开 SDK 里没有，编译必失败。见第 8 节。

2.3 为什么不用 Camera2（重要背景）
    Camera2 的外接相机（external camera）只有少数机型的固件支持，
    绝大多数手机/车机根本不认 UVC 摄像头。libuvc 方案走 USB 原生视频流，
    兼容性最好，代价是需要自己处理 USB 权限和 isochronous 传输。

3. 工程结构（每个文件干什么）

    MainActivity.kt          全部界面：全屏预览 + 工具条 + 菜单 + 弹窗

4.1 v1.0 基础功能（已完成）
----------------------------------------------------------------
需求 1：实时预览
    实现：CameraCore.onCameraOpen → helper.startPreview()，

    实现：CameraCore.startRecording()，H.264 + AAC，
          码率 12Mbps、30fps、关键帧 1 秒。
    契约：没有麦克风权限时自动录无声视频（setAudioCaptureEnable(false)）。

    实现：菜单“分辨率 / 格式” → 列出 MJPEG/YUYV × 分辨率 × 帧率，

          不要自己写死列表。

需求 5：旋转 / 镜像
    实现：CameraPreviewConfig.setRotation(0/90/180/270)、setMirror(...)。
    契约：旋转每次 +90°，镜像按 关→水平→垂直 循环。

需求 6：多摄像头
    实现：菜单“摄像头”列出所有 UVC 设备，切换时 CameraCore.switchTo()
          （先 close，等 onCameraClose 回调再 open，避免竞态）。

    实现：进入前记录 AudioManager.isMusicActive；

          调用 dispatchMediaKeyEvent(KEYCODE_MEDIA_PLAY)。
    契约：没在放音乐时绝不能乱发 MEDIA_PLAY（会误唤醒播放器）。

          c) 关闭开关必须立刻恢复等比 + 黑边，不需要重开摄像头。

6. 关键实现细节（照抄，勿“优化”）
================================================================
6.1 音频焦点（DrivingAudio.kt）
    - 请求：AUDIOFOCUS_GAIN（不是 TRANSIENT），API 26+ 用 AudioFocusRequest。
    - 记录 pausedMusic = am.isMusicActive（请求前读取）。
    - 退出：abandonAudioFocus(+Request)，若 pausedMusic 为真，
      500ms 后发 KEYCODE_MEDIA_PLAY 的 DOWN/UP 两个 KeyEvent。
    - 播放顺序：抢焦点 → DrivePlayer.play() → 失败才 TTS。

6.2 热键（HotkeyService.kt）
    - onKeyEvent 只处理 ACTION_DOWN 且 repeatCount==0。
    - 修饰键用 event.isCtrlPressed / isAltPressed / isShiftPressed
      拼成 KeyEvent.META_CTRL_ON 等，与 Prefs 存的 mods 比较。
    - 启动：Intent(this, MainActivity::class.java)
        .addFlags(NEW_TASK | REORDER_TO_FRONT | SINGLE_TOP)，startActivity。
    - 退出：AppState.hideToBackground() → Activity.moveTaskToBack(true)。

6.3 摄像头生命周期（CameraCore.kt）
    - 状态：IDLE / OPENING / PREVIEW / ERROR。
    - 输出面用 Map<String, SurfaceTexture> 管理，key 取 "activity" / "float"，
      两个面可以同时挂载（App 前台 + 悬浮窗）。
    - 打开流程：selectDevice → onDeviceOpen → openCamera()
                → onCameraOpen → startPreview() → 给所有已登记的面 addSurface。
    - 切换设备：switchTo() 先 close，onCameraClose 里再 open(pendingDevice)。
    - Activity onStop：若没开悬浮窗 → 停录像 + close()（省电、释放 USB）；
      开着悬浮窗 → 摄像头保持出流。

6.4 悬浮窗（FloatWindow.kt）
    - 窗口类型：API 26+ 用 TYPE_APPLICATION_OVERLAY，否则 TYPE_PHONE（已废弃）。
    - 触摸：ScaleGestureDetector 处理双指缩放；单指算 rawX/rawY 增量移动。
    - 关闭：右上角 “×”，hide() 里 removeView + 若 App 不在前台则 close 摄像头。

6.5 媒体保存（MediaStoreExport.kt）
    - Android 10+：ContentResolver.insert + RELATIVE_PATH
      （Pictures/USBCam、Movies/USBCam）+ IS_PENDING 1→0，成功后删源文件。
    - Android 10 以下：不做处理，文件留在 App 私有目录。

6.6 构建期生成语音（可选兜底）
    - CI 步骤 “生成内置语音”：若 res/raw 下没有 drive_warning.*，
      则 apt 装 espeak-ng 并合成一段 wav。
    - 现在仓库里有 mp3，这一步会自动跳过。

7. 构建与发布
================================================================
7.1 云端构建（唯一在用的方式）
    .github/workflows/build-apk.yml 步骤：
      1) checkout
      2) setup-java 17 (temurin)
      3) 用运行器自带 Android SDK：
         SDK="${ANDROID_HOME:-/usr/local/lib/android/sdk}"
         sdkmanager --licenses（yes 管道）
         sdkmanager --install "platform-tools" "platforms;android-35" "build-tools;35.0.0"
      4) 下载 Gradle 8.9 到 $RUNNER_TEMP，写进 GITHUB_PATH
      5) （可选）espeak 生成提示音
      6) gradle :app:assembleDebug --no-daemon
      7) upload-artifact：name=usbcam-debug-apk，
         path=**/build/outputs/apk/debug/*.apk
    产物：GitHub Actions 运行页最底部 Artifacts → 下载 zip → 里面 app-debug.apk。

7.2 重要：不要用 android-actions/setup-android@v3
    它内部会执行 `sdkmanager tools`，新版 cmdline-tools 已删除 tools 包，
    必然报 “Failed to find package 'tools'” 并让整个 job 失败。
    必须用 7.1 第 3 步的手动方式。

7.3 仓库与上传的两个坑
    - Windows 资源管理器默认隐藏以点开头的文件夹，拖拽上传会丢掉 .github，
      导致 Actions 一直显示 “Get started with GitHub Actions” 页面。
      解决办法：在网页上 Add file → Create new file，
      文件名填 .github/workflows/build-apk.yml，粘贴内容后提交（只需一次）。
    - 仓库里没有 gradle-wrapper.jar，本地用 Android Studio 打开时
      需要指定本地 Gradle 8.9+，或先执行 gradle wrapper。
    - 每次改代码只需拖 app 文件夹覆盖，工作流不用再动。

7.4 本地构建（不推荐，环境需自行准备）
    JDK 17 + Android SDK Platform 35 + Build-Tools 35.0.0 + Gradle 8.9。

8. 踩过的坑（换 AI 后极可能重犯，务必先读）
================================================================
坑 1：setup-android@v3 编译前就失败
    现象：sdkmanager 报 Failed to find package 'tools'。
    原因：该 action 内部执行 sdkmanager tools。
    修复：删掉该 action，改用手动 sdkmanager（见 7.1）。

坑 2：Kotlin 找不到 ImageCapture.OutputFileOptions
    现象：Unresolved reference 'OutputFileOptions' / 'OnImageCaptureCallback'。
    原因：Java 允许通过子类型访问接口的嵌套类，Kotlin 不继承嵌套类。
    修复：写成 IImageCapture.OutputFileOptions、
          IImageCapture.OnImageCaptureCallback、IImageCapture.OutputFileResults。

坑 3：KeyEvent.META_MODIFIER_MASK 编译不过
    现象：Unresolved reference 'META_MODIFIER_MASK'。
    原因：Android 的 @hide 常量，公开 SDK 里没有。
    修复：用 event.isCtrlPressed / isAltPressed / isShiftPressed 自己拼。

坑 4：Actions 一直是 “Get started” 页面
    原因：仓库里没有 .github/workflows（拖拽上传丢了隐藏目录）。
    修复：网页新建该文件一次即可（见 7.3）。

坑 5：退出后音乐不续播
    原因：只 abandon 焦点，部分车机播放器不会自动恢复。
    修复：记录 isMusicActive，退出时补发 KEYCODE_MEDIA_PLAY。

坑 6：espeak 生成的中文很机械
    修复：改用用户录音 res/raw/drive_warning.mp3，CI 检测到文件就跳过合成。

坑 7：Android 14 启动前台服务崩溃
    原因：camera 类型的 FGS 要求已授予 CAMERA 权限；
          microphone 类型要求 RECORD_AUDIO。
    修复：只在有权限时启动；startForeground 的 types 按权限按位拼；
          整个调用包 try/catch，失败 stopSelf。

坑 8：切换摄像头点了没反应
    原因：closeCamera 是异步的，紧接着 open 会被状态机挡掉。
    修复：switchTo() 记 pendingDevice，在 onCameraClose 回调里再 open。

坑 9：USB 键盘被当成摄像头
    修复：devices() 按 interfaceClass==14 过滤，过滤为空才退回原列表。

9. 代码约定（Do / Don't）
================================================================
DO
    - 新增界面元素：在 MainActivity.buildUi() 里用代码创建并 addView。
    - 新增菜单项：在 buildMenu() 里用 addRow / addSwitchRow。
    - 新增持久化：统一加到 Prefs.kt，键名用下划线小写。
    - 新增摄像头能力：放在 CameraCore，界面只调用它。
    - 所有摄像头/媒体回调都 post 到主线程再更新 UI。

DON'T
    - 不要引入任何新依赖（尤其是 UI 库、协程库、图片库）。
    - 不要把 CameraHelper 放到 Activity 里（会导致后台/悬浮窗失效）。
    - 不要用 R.raw.xxx 直接引用音频（文件缺失会导致编译失败），
      必须用 resources.getIdentifier。
    - 不要改包名、applicationId、主题，否则用户已授权的无障碍服务会失效。
    - 不要在 onStop 里关闭摄像头（有悬浮窗时不能让流断掉）。
    - 不要用 MaterialAlertDialog / AppCompat 主题。
